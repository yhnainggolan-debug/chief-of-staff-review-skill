# Output and action modes

## Default boardroom mode

Use unless the user requests depth:

**Verdict** — maximum two sentences. Include artifact readiness and decision sufficiency when both matter.

**What changes the outcome** — maximum three ranked bullets, each anchored.

**Questions I would ask** — maximum three.

**Call / next move** — one line.

## Deep mode

Use for high-stakes approval materials or when requested:

1. Bottom line and two-axis readiness
2. Decision and audience
3. What is supported
4. Material gaps and red flags
5. Economics and sensitivities
6. Execution, risk, and governance
7. Questions that could change the call
8. Required revisions and final recommendation

Do not repeat the same issue across sections.

## Room-read mode

Use for presentation judgment:

1. Five-second reaction
2. What makes the audience lean forward
3. Where credibility or attention drops
4. Exact sequence or copy changes
5. Transition into action and decision
6. Delivery QA, including mobile/fallback when relevant

## Rewrite spine

Rewrite the decision argument as a concise sequence: current reality, tension, mechanism, evidence, near-term moves, value, and ask. Preserve verified facts and label open assumptions.

## Redline content

Provide exact replacement copy tied to anchors. Explain only changes where the rationale is not obvious.

## Source-first revision

When authorized to edit, update the canonical markdown, memo, model, or content specification before downstream HTML, slides, exports, or visuals. Verify that artifacts remain aligned.

## Question pack

Return only the few questions to send management, grouped by decision impact. Each question should state why the answer matters when useful.

## External context

Do not perform routine headline searches. Search only if current market, policy, regulatory, counterparty, technology, or sector developments could materially alter the review. Cite the source and date, and explain the decision implication.
